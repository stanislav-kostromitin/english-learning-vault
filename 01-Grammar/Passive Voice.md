# Passive Voice

## Meaning

Use Passive Voice when the focus is on the action, result, or affected object, not on who did it. This is common in QA reports, incident updates, and release notes.

## Structure

```text
be + V3
Present Simple: The issue is reproduced.
Past Simple: The bug was fixed.
Present Perfect: The fix has been verified.
Continuous: The report is being reviewed.
```

## QA / Work Examples

- The issue was reproduced in staging.
- The test suite was updated last night.
- The fix has already been verified.
- The deployment was delayed because of a blocker.
- The report is being reviewed by the team.

## Contrast

- Active: I verified the fix. Focus: I did it.
- Passive: The fix was verified. Focus: the fix/result.

Use active voice when the doer matters. Use passive voice when the result/status matters more.

## Common Mistakes

- Wrong: The bug fixed yesterday.
- Better: The bug was fixed yesterday.
- Reason: Passive Voice needs `be + V3`.

- Wrong: The fix has verified.
- Better: The fix has been verified.
- Reason: Present Perfect Passive uses `has/have been + V3`.

## Practice

- Turn "I verified the fix" into Passive Voice.
- Write one incident update using passive voice.
- Write one release note sentence using passive voice.

## Key Idea

Passive Voice moves attention from the doer to the action/result.
