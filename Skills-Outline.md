# Skills Outline

Не обязательный к немедленной реализации файл - фиксирует роль и разделение
policy/guidance для будущих Claude Code skills, если решишь их писать (по образцу
`java-*-v4`). Пока весь функционал выполняется одним `CLAUDE.md` + `COURSE_RULES.md`
без отдельных skill-файлов - это нормально для текущего масштаба проекта, дробить
на скиллы имеет смысл, когда одна инструкция станет слишком длинной/запутанной, а не
заранее "для полноты архитектуры".

Каждый skill тестировать через `skill-creator` минимум на 2-3 сценариях перед тем,
как считать готовым.

## language-brain
- **Роль:** boot-скилл, грузится первым в любой активной сессии.
- **Действие:** читает `COURSE_RULES.md`, `09-Progress/Progress Tracker.md`,
  `03-Mistakes/Mistake Journal.md`, due-карточки - до предложения темы урока.
- **Policy:** сессия не начинается без этого чтения.

## vocab-intake
- **Роль:** ввод новой лексики в `02-Dictionary/`.
- **Policy:** новое слово вводится в контексте (QA-пример) до того, как пользователя
  просят использовать его самостоятельно.
- **Guidance:** выбор конкретного примера под рабочую ситуацию пользователя.

## grammar-notice
- **Роль:** введение грамматической темы в `01-Grammar/`.
- **Policy:** пример → объяснение → проверка (output push), согласно "Focus on Form"
  в `COURSE_RULES.md`.
- **Guidance:** глубина объяснения, выбор QA-аналогии.

## error-log
- **Роль:** ведение `03-Mistakes/Mistake Journal.md`.
- **Policy:** статус `resolved` только если ошибка не появлялась несколько уроков
  подряд И пользователь воспроизвёл правильную форму под давлением - это уже
  сформулировано в `COURSE_RULES.md`, здесь просто явно закрепляется как проверяемое
  условие, а не пожелание.

## session-orchestrator
- **Роль:** распределение блоков урока (Review/Grammar/Speaking/QA/Vocabulary из
  таблицы "Lesson Structure" в `COURSE_RULES.md`).
- **Policy:** пропорции блоков не должны нарушаться "потому что тема интересная" -
  особенно долю Speaking/production (40%).

## progress-review
- **Роль:** обновление `Progress Tracker.md` и `CEFR Checklist.md`.
- **Policy:** CEFR-дескриптор закрывается только по накопленным эпизодам (см. CEFR
  Checklist.md, "Как заполняется"); стадия Automation в Progress Tracker - только по
  демонстрации под давлением, не по объяснению.
